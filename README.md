# 每日工作日誌

一個 macOS app，把你的工作日誌畫成月曆與看板。

日誌是 Claude Code 每天幫你寫的 markdown 檔，一天一個。這個 app 讀那些檔，
算出「每天做了什麼」與「每支工作項目走到哪一步」。

## 安裝

到 [Releases](https://github.com/amoeric/worklog/releases/latest) 下載 `.dmg`，打開，
把 app 拖進「應用程式」。

第一次開會問兩件事，兩個都要**允許**：

- 「無法驗證開發者」→ 在 app 上按右鍵選「打開」
- 「想要取用你『文件』檔案夾中的檔案」→ 不允許就讀不到日誌

## 第一次設定

**1. 選日誌資料夾。** 預設是 `~/Documents/Obsidian Vault/每日工作日誌`，
要換就到「設定 → 選資料夾… → 儲存並重讀」。

**2. 確認 Claude 會幫你寫日誌。** 這個 app 只讀檔，不產生日誌。真正在寫的是 Claude Code，
它照的是 `~/.claude/CLAUDE.md` 裡「# 每日工作日誌」那一段規則。

沒有那段規則 → app 會沒東西可讀。到「設定 → 日誌規則」按「還原成預設」再按「套用到 Claude」，
就會把規則寫進去（寫之前會備份）。

## 日誌檔長什麼樣

app 只讀 `<年>/<月>/` 底下、檔名是八碼數字的 `.md`，例如 `2026/08/20260817.md`。

```markdown
## chat_hub

- `已歸檔` [feat: 對話頁補上左側清單](http://gitlab.example.com/group/chat_hub/-/merge_requests/64)
- `暫存` [search-history：對話紀錄搜尋](https://redmine.example.com/issues/32979)
- `完成` 議題對帳：兩邊未結案數對齊
  - 補建三支提案的互連議題
```

- `## 名字` 是專案
- 每行開頭的行內程式碼是**狀態**，只有這八個算數：
  待辦、提案中、暫存、實作中、測試中、待合併、已歸檔、完成
- `slug：描述` 的 slug 是**工作項目代號**，同一件事每次都寫同一個 slug，才會併成同一支
- 縮排兩格的子 bullet 是**詳情**

讀不懂的行不會被吞掉，會列在設定頁的「沒讀懂的行」。

### 摘要與詳情

一條日誌是「摘要一行 ＋ 選擇性的詳情」：

```markdown
- `實作中` search-history：對話紀錄搜尋
  - 全文搜尋改用 pg_trgm，中文斷詞交給 pg_bigm
  - 分頁還沒做，明天接
```

摘要一句話講完，細節放詳情。詳情只放 MR / issue 上沒有的東西：當下的判斷、卡住的地方、
明天要接的事。大部分的事只要一行摘要。

- **日誌頁**：摘要右邊有箭頭與數字，點了才展開
- **工作項目頁**：詳情直接攤開
- **看板**：只顯示摘要

## 五個分頁

| 分頁 | 看什麼 |
| --- | --- |
| 月曆 | 首頁。整個月每天列出各狀態幾筆，點某天進看板 |
| 看板 | 一個狀態一欄，卡片可以拖著改狀態 |
| 日誌 | 一天一天讀，可選單日／7 天／30 天／全部／自訂起訖 |
| TODO | 隨手記，可以一鍵寫進今天的日誌 |
| 設定 | 資料夾、外部服務、日誌規則、讀到幾個檔 |

月曆、看板、日誌三頁左上角有搜尋框，打字就地過濾。多個關鍵字用空白隔開，每個都要命中。
Esc 清空、⌘F 聚焦；關鍵字記在網址，重新整理還在。

**看想看的那段時間**：看板與日誌都可以只看某一天或某一段。
選「一段期間」時日曆會自己打開，**點一天當起始、再點一天當結束**（先點晚的也可以）。
選好的兩端是紅色，中間淡底。← → 換日或整段前後移動。

**TODO 頁的四顆按鈕**：編輯、加到今日日誌、複製 md、刪除。
「複製 md」是把那一行 markdown 複製起來，方便直接貼給 Claude；
「刪除」只刪 app 裡的 TODO，不動日誌檔。

## 工作項目

日誌檔裡沒有「工作項目」這種東西，是 app 從條目算出來的。同一支 change 在不同天各寫一行，
會被併成一支項目，串成一條歷程。

**怎麼併**：最主要看 slug（`slug：描述` 開頭那個）。沒寫 slug 的話會試著靠連結、
靠隔壁的封存行去認；都認不出來，那一行就自己成為一支項目。

**目前狀態＝最後一筆有標狀態的條目**。要推進狀態就在今天的日誌加一行，或直接在看板上拖卡片。

點卡片標題進去是那支項目的歷程頁，看得到它每一天走到哪裡。

### `_items.md`：讓 Claude 記得 slug

Claude 每天開新對話，記不得前幾天用過哪些 slug，就會替同一件事另外取一個，
那支 change 於是在看板上裂成好幾張卡。

所以 app 會在日誌資料夾根目錄產一份 `_items.md`，列出還沒結束的工作項目與 slug，
規則本文叫 Claude 動筆前先讀它照抄。

這個檔是 app 產的，**不要編輯**，改了下次開 app 會被蓋掉。

### Spectra 標記

帶 slug 的工作項目就是一支 Spectra change，前面會顯示 Spectra 的 app icon。
出現在看板卡片、狀態清單頁、工作項目頁標題。

## 狀態可以自己加

內建八個之外，看板最右邊可以再加一欄。填名稱、一句說明、插在哪一欄後面，顏色自動配。

加完會問要不要把它寫進 `~/.claude/CLAUDE.md` 的日誌規則——**不寫進去的話，看板認得它，
但 Claude 寫日誌時不會用它**。

自訂的可以刪（欄頭右上角的叉），內建八個刪不得。刪掉不動日誌檔一個字，
已經寫成那個標籤的行留在原地，只是 app 之後不認得。

## 它會動你哪些檔案

只有兩個地方會寫日誌檔，而且都**只動今天那一個檔**：

**TODO 頁的「加到今日日誌」** — 在對應的 `## 專案` 區塊插一行。既有的行一個字都不動，
也不重排。一模一樣的行同一天只寫一次。

**看板拖卡片** — 今天已經有那支項目的行，就只換行首的狀態標籤（標題、連結、括號補充
一個字都不動）；今天還沒有才新增一行。

兩個都**沒有復原**，改錯了要自己去 md 改回來。寫不進去的時候會用紅字說明原因，
而且看板會退回原本的樣子，畫面不會顯示一個檔案裡沒有的狀態。

日誌規則那一區是例外：它改的是 `~/.claude/CLAUDE.md`，只換「# 每日工作日誌」那一段，
寫之前備份成 `CLAUDE.md.bak-<西元8碼>-<時分秒>`，而且**只有按下按鈕才會寫**。

app 自己的設定與 TODO 存在 `~/Library/Application Support/tw.npust.worklog-app/`，
不會寫進日誌資料夾。

## 在 app 裡看 MR 與議題

設定頁的「外部服務」填 GitLab 與 Redmine 的位址與 token，之後點日誌裡的 MR／議題連結
就不會跳瀏覽器，而是在 app 裡開面板：標題、狀態、幾行資訊、描述全文、留言。
面板下方一定有「在瀏覽器開啟」。

- 描述與留言裡的圖片會真的顯示出來（那些圖多半要帶 token，所以是後端代抓的）
- 讀不到就直接寫是哪一種問題（沒設 token、認不出網址、401、連不上、逾時），不會卡住
- token 存在 app 自己的設定檔，**不會**寫進日誌資料夾，存好之後畫面也不再顯示
- 如果設定的位址跟連結的主機不一樣，app 會停下來說明原因，不會把 token 送到別台機器

其餘連結維持原本行為：丟給系統瀏覽器。

## 更新

開 app 之後會在背景查一次有沒有新版，有的話右上角浮一則提示。
也可以到「設定 → 版本與更新」自己按檢查。

這個 app 沒有 Apple 公證，所以線上更新**有可能被 macOS 擋掉**。失敗時畫面會寫出是哪一種問題，
旁邊一直留著「開啟下載頁」，隨時可以自己抓 `.dmg` 換。

## 已知限制

- 沒有簽章與公證，只適合自己用
- 拖曳只在桌機有效；窄視窗請用卡片上的下拉選單改狀態
- 看板改狀態沒有復原
- 歸戶失敗的條目只能靠改日誌檔的寫法修正，app 裡不能手動指派
- 同一支 change 的議題與 MR 如果沒有共同的 slug 或連結，會被算成兩支。
  要合併就在標題前面補 `slug：`
